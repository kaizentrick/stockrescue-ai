# Colaborar sin pisarnos

1. Consultar `docs/TASKS.md` y reservar una tarea en un PR o issue antes de editar.
2. Actualizar referencias con `git fetch origin`. Crear rama desde main o la rama base acordada: `feat/<persona>-<tarea>`.
3. No subir directamente a main; no usar force push sobre ramas compartidas.
4. PR pequeño con alcance, evidencia y comprobaciones. Mantenerlo borrador hasta revisión.
5. No fusionar PR de otra persona sin acuerdo. Revisar cambios remotos antes de cada push.
6. No subir llaves, tarjetas, datos reales, archivos .env ni expedientes locales.

Josmar puede elegir interfaz, pruebas, caso comercial o demo. No se le asigna backend por defecto. El acceso requerido es escritura para código, nunca administración.
